# 7.4 链接器与编译器前端的协同机制

在传统编译工具链中，编译器前端（如 Clang、Rustc）与链接器（如 GNU ld、LLVM lld）通常被拆分为独立的子工具：前端生成中间目标文件写入磁盘，链接器以独立进程读取这些文件并输出最终二进制。

而在 Zig 0.17 中，编译器前端与自研链接器运行在**同一个进程空间与统一的数据结构体系下**。

这种端到端协作使 Zig 实现了若干特殊的工具链特性。

---

## 协作特性 1：全自动错误返回追踪（Error Return Traces）

Zig 提供了细致的错误追踪能力：当函数返回错误时，控制台能打印出该错误具体的生成点以及沿调用栈向上冒泡传递的完整路径。

在传统编译环境中，类似功能通常需要依赖重型的异常处理展开表（如 DWARF `.eh_frame`、Itanium C++ ABI）或引入外部回溯库（如 `libunwind`）。

而在 Zig 中（查看 [`src/Compilation.zig#L3001`](https://codeberg.org/ziglang/zig/src/tag/0.17.0/src/Compilation.zig#L3001)）：
```zig
link.updateErrorData(pt);
```
- **Sema 阶段**：编译器前端在进行类型推导时，分析出全局所有的错误码（Error Tag）以及每个函数的推断错误集合（Inferred Error Set）；
- **链接阶段**：自研链接器直接从前端共享内存中读取该错误集合，在生成的二进制数据段中**直接注入轻量的错误元数据表**；
- **运行期**：程序在无需动态堆分配的情况下即可输出完整的错误回溯栈。

---

## 协作特性 2：内置测试运行驱动器（`zig test`）

在传统语言中构建单元测试，通常需要以下步骤：
1. 借助宏收集测试函数；
2. 生成包含测试逻辑的目标文件；
3. 生成一个临时的 `main()` 入口测试驱动源码；
4. 再次编译驱动文件并调用链接器合成测试程序。

而在 Zig 中（查看 [`src/Compilation.zig#L2994-L3000`](https://codeberg.org/ziglang/zig/src/tag/0.17.0/src/Compilation.zig#L2994-L3000)）：
```zig
if (comp.config.is_test) {
    // 延迟搜集所有未被过滤的测试函数列表
    try pt.populateTestFunctions();
}
```
前端在分析代码时，每识别到一个 `test "..." { ... }` 块，直接将其函数符号登记入 `Zcu` 的测试函数注册表；
当进入链接阶段时，自研链接器直接在二进制内部合成一个测试执行器函数数组，**无需在磁盘上生成中间测试入口文件，也无需二次链接**。

---

## 阶段总结

通过第 7 部分的分析，我们梳理了 Zig 自研链接器的设计要点：
- 采用常驻内存模型规避外部链接器的冷启动损耗；
- 自研 ELF、Mach-O、COFF 与 WASM 四大原生链接器；
- 结合内存映射（`MappedFile`）实现原位增量二进制更新；
- 前端与链接器深度协同，支持错误栈回溯与轻量测试驱动合成。
